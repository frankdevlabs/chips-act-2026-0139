## Assessment

### `T1-13` — not a layout change; the listing is now AWS-WAF-blocked

Re-probed live on 2026-08-06. The "page layout changed?" diagnosis is a **false negative**:

- A plain fetch of the listing (both the tracker.yaml `/en/itre/…` URL **and** the
  `committeeMnemoCode=ITRE` form the parser actually polls) returns **HTTP 202, 0 bytes** — the
  AWS-WAF JS challenge, the same block that already hits doceo and EUR-Lex `legal-content`.
- `ep_committee_docs.py` fetches with plain `urllib` (see `_fetch`, `~/law-tracker/lib/ep_committee_docs.py:59`).
  `urllib` treats the 202 challenge as a normal response and hands its HTML — which contains **zero**
  `es_document` blocks — to `parse()`. The parser's only failure mode for an unparseable page is
  `return 2` + *"no es_document blocks found (page layout changed?)"* (`ep_committee_docs.py:170`), so a
  WAF block is **mislabelled** as a layout change. (The issue says "HTTP 200"; the challenge status is
  actually 202, which `urllib` does not raise on — same observable result.)
- **The layout is unchanged.** Fetched through the browser tier
  (`fetch_blocked_doc.py`, which solves the WAF) the page is **304 886 bytes** and contains **80
  `<div class="es_document ">` blocks** — the exact fragment the parser splits on
  (`_BLOCK_RE = r'<div class="es_document "\s*>'`, `ep_committee_docs.py:50`), plus the matching
  `es_document-title` / `-subtitle-fragment` / `-subtitle-pdf` markup the record parser reads. No
  selector needs to change.

**Verdict:** the source is healthy and the parser's selectors are correct; the defect is that the
listing endpoint moved behind AWS-WAF and the parser's plain-`urllib` fetch can no longer clear it.
Two things to fix: (1) *in-repo* — record the WAF signature in the `T1-13` `notes` so a future run reads
"blocked, fetch via browser tier" instead of chasing a phantom layout change, and align the human-facing
`url` to the endpoint actually polled; (2) *infra, out of this repo* — teach `ep_committee_docs.py` to
fetch through the browser tier (or to detect the 202 challenge and exit with a distinct "blocked" signal
rather than "layout changed"). Only (1) is a repo edit; (2) is flagged as the real remediation below.
